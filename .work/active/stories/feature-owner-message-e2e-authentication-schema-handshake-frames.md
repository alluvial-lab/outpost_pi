# Schema + codegen for handshake frames

## Brief

Extend `protocol/schema/app-pi-client.schema.json` (`pair_request` + `dh_pk`, `dh_sig`) and `app-pi-server.schema.json` (`pair_ok` + `dh_pk`, `dh_sig`); regenerate TS + Dart DTOs; extend fixtures including the known-answer AEAD/HKDF vector (fixed DH keys, token, seq, plaintext → exact sealed frame bytes).

Acceptance: generated `PairRequest`/`PairOk` carry `dhPk`/`dhSig` in TS + Dart; `protocol/` checks pass; KAT vector committed.

Design: see the parent feature body's Implementation Units and Cryptographic
design sections — this story is a checkpoint of that design, not a
standalone spec.

## Implementation notes

- Added optional `dh_pk` and `dh_sig` fields to `pair_request` and `pair_ok`,
  while wave-2 handshake handlers will require and fail closed on them. The
  optional schema boundary keeps existing app and extension consumers compiling
  during this coordinated wave.
- Added `bad_dh_sig` to the schema-owned `PairErrorCode`, regenerated the TS and
  Dart contracts, and refreshed pairing fixtures with the matching KAT values.
  The protocol-codegen assertion was updated to expect the expanded generated
  enum.
- Added deterministic `protocol/fixtures/app-pi/owner-channel-kat.json`,
  generated by `protocol/scripts/generate-owner-channel-kat.ts` via
  `node --import tsx scripts/generate-owner-channel-kat.ts`. It fixes X25519
  and Ed25519 keys, token, nonces, transcripts, HKDF keys, signatures, and
  XChaCha20-Poly1305 frames. Sequence number is the 8-byte LE AEAD AAD.
- Added `@noble/curves` and `@noble/ciphers` protocol dev dependencies. No
  design deviations: the specified `seqLE64 || jsonUtf8` construction is
  represented as `seqLE64` associated data plus JSON plaintext.
- Verified protocol fixtures and codegen tests, extension typecheck, app
  protocol-codegen tests and analysis, plus byte-identical KAT regeneration.
